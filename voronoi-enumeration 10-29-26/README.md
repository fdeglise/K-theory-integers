# Small-rank Voronoi cell enumeration

There is now also a [C++ implementation for ranks 1--7 and small cone-dimension
excess](cpp/README.md), using GMP and exact SoPlex LP closure. The Python code
below remains the independent rank-1--4 reference implementation.

The [conversation transcript](TRANSCRIPT.md) records the development discussion.
The [publication note](DEVELOPMENT-2026-10-29.md) states the scope, validation,
and relationship to the repository's existing rank-eight verifier.

An exact Python reference implementation of the proposed **minimal-vector frame
and Ryshkov-slice face search**. It enumerates full-vector-rank cells modulo
`GL_n(Z)` for **n = 1, 2, 3, 4**. It uses only the Python standard library, requires
Python 3.10 or newer, and performs all arithmetic with `fractions.Fraction`.

```sh
python3 voronoi.py 2
python3 voronoi.py 3 --json cells_n3.json
python3 voronoi.py 3 --max-cone-dimension 4
python3 voronoi.py 4 --json cells_n4.json --verbose
python3 -m unittest -v
```

The complete counts are:

| Lattice rank | Cone dimension -> number of cell orbits |
| --- | --- |
| 1 | 1 -> 1 |
| 2 | 2 -> 1, 3 -> 1 |
| 3 | 3 -> 1, 4 -> 2, 5 -> 1, 6 -> 1 |
| 4 | 4 -> 1, 5 -> 3, 6 -> 4, 7 -> 4, 8 -> 2, 9 -> 2, 10 -> 2 |

**Projective cell dimension is cone dimension minus one.** Every output cell
meets the positive-definite locus. Cells supported on a proper vector subspace
are boundary cells and are excluded.

The two rank-3 cones of dimension 4 are distinguished by a triangle with an
extra edge versus a four-cycle in the graphic description of the A3 cone.

Rank 4 has **18 cell orbits**. Its two maximal cones are A4 (10 rays, stabilizer
order 240) and D4 (**12 rays in dimension 10**, stabilizer order 1152). Orders
include `-Id`. Both stabilizers contain orientation-reversing elements. The
complete rank-4 counts agree with
[Dutour Sikiric--Hulek--Schurmann, Table 1](https://content.algebraicgeometry.nl/2015-5/2015-5-027.pdf).
The checked-in `cells_n4.json` contains all 18 exact representatives and witnesses.

## What the code actually does

1. Enumerate integral frame matrices `B` in **row Hermite normal form**, under
   left unimodular action. In frame coordinates the ambient lattice is
   `L = B^{-1} Z^n`, containing `Z^n`, of index `I = det(B)`.
2. Build a finite rational halfspace description of the normalized Ryshkov slice
   with `G_ii = 1` and `G[x] >= 1`. In ranks 1--3, enumerate its vertices by
   solving every square active-constraint system exactly. Rank 4 instead uses
   exact **incremental halfspace clipping**: start with the valid box
   `|G_ij| <= 1/2`, intersect each lattice inequality, and construct new vertices
   along certified edges. Two vertices share an edge precisely when their
   common active normals have rank `k-1`, where `k=n(n-1)/2`. The algorithm
   supports nonsimple vertices and slices that collapse to a lower dimension.
3. Starting from the entire slice, intersect faces with supporting walls.
   Represent a face by the complete set of vertices it contains. Their average
   is a rational relative-interior point; its complete active set automatically
   includes forced additional minimal vectors. Prune when the rank of the
   matrices `xx^t` exceeds the requested cone dimension. No simpliciality
   assumption is used by the face search or orientation calculation.
4. Verify each face's minimal-vector set by a separate exhaustive search of its
   ellipsoid. Convert vectors back to integral ambient coordinates using `B`.
5. Bucket configurations using the intrinsic positive-definite matrix
   `C = sum(v*v^t)`, and test integral equivalence by extending a fixed frame
   using the pairings `v^t*C^-1*w`. Every accepted map is checked for integral
   entries, determinant +/-1, and preservation of the complete vector-pair set.
   This works even when the fixed comparison frame is nonunimodular. Compute
   canonical representatives only for new orbits; in rank 4, intrinsic Gram
   tuples filter the signed ordered unimodular frames. Calculate the exact
   stabilizer and its action on the span of `xx^t` to detect orientation reversal.

This prototype enumerates vertices **within each frame slice** as a convenience;
that is not intended as a scalable strategy for high ranks. The production
version would replace it with exact LP, shortest-vector separation, and a
closure oracle operating directly on faces.

The default rank-4 run constructs 304 vertices of the index-one frame slice and
visits 5354 faces across the 16 frame models before deduplicating to 18 orbits.
This remains a reference implementation, not a scalable rank-11 search engine.

## Why the search is complete in these ranks

### Frame index bound

Normalize the lattice minimum to one. A parallelepiped generated by independent
minimal vectors has volume at most one by Hadamard's inequality. Minkowski's
convex body theorem bounds the ambient lattice's covolume below by the volume
of the unit ball divided by `2^n`. Thus the index of **every** minimal-vector
frame is at most `2^n / vol(Ball_n)`.

For n=1,2,3 the integer bound is **1** (for n=3, `6/pi < 2`). Therefore every
independent minimal-vector frame in these ranks is unimodular.

In rank 4 the sharp frame index bound is **2**, from `gamma_4 = sqrt(2)` and
the Hermite/Hadamard inequality `I <= gamma_n^(n/2)`. One can also obtain it
elementarily: Minkowski gives `I <= 32/pi^2 < 4`, and index 3 is impossible.
For an index-3 frame, write a nontrivial coset representative as
`x=(sum(a_i*e_i))/3`, with `a_i` in `{-1,0,1}` and support size `s<=4`.
Then

```
sum_{a_i != 0} (G[e_i - sign(a_i)*x] - G[e_i]) = (s - 6)*G[x] < 0,
```

contradicting minimality of the `e_i`. The default bound is therefore 2 in
rank 4, and explicitly requesting a smaller bound is rejected. The catalogue
has one index-one and 15 index-two frame models.

Although a chosen rank-4 frame can have index two, every realizable complete
minimal configuration still contains a unimodular frame. For an index-two
superlattice, represent the nontrivial coset by `a/2` with `a_i` equal to zero
or one. Averaging the values of all sign choices of `a/2` gives `support(a)/4`.
Minimality forces support four, and every sign choice must then have value
one. Replacing one frame vector with a half-sum gives a unimodular minimal
frame. This justifies canonicalization using unimodular frames in rank 4.

In fact this index-two slice is a **single point**: all six off-diagonal
entries vanish and all 12 pairs of D4 minimal vectors are forced. The test
suite exercises this without assuming the cone is simplicial.

For ranks 1--3, `--index-bound 2` exercises the frame catalogue and finite-pool
logic with a larger valid bound; it must produce the same orbits. Increasing
the index bound does not enable higher lattice ranks.

### A finite set of inequalities

Let `D` be the index bound and fix a frame of index `I`. Every vector minimal at
any point of its true slice belongs to

```
C = { x in L, x != 0 : |x_i| <= D/I for every i } / {+1,-1}.
```

Indeed, replacing frame vector `e_i` with a minimal vector `x` gives a frame of
index `I*|x_i|` when `x_i != 0`. Its index cannot exceed `D`.

Define `P_C` by `G_ii=1` and the inequalities for this finite pool. **If the true
slice is nonempty, P_C equals the true slice.** To see this, the true slice is
compact inside the positive-definite cone: `e_i +/- e_j` bound all off-diagonal
entries, and the lattice minimum condition excludes singular and indefinite
limits. Local finiteness of the Ryshkov polyhedron supplies a finite defining
set of lattice inequalities. After removing redundancies, each defining
inequality is active somewhere and its vector must belong to `C`.

Consequently an arbitrary rational point of a nonempty `P_C` determines the
frame's feasibility: a positive-definite point of minimum one certifies that
`P_C` is the true slice; a point failing that test proves the true slice empty.
The code uses the vertex barycenter for this check. It does not discard a
feasible frame merely because an arbitrary relaxed LP solution was unsuitable.

For the separate ellipsoid checks, `G[x] <= 1` implies
`x_i^2 <= (G^{-1})_ii`. The code enumerates the resulting finite lattice box
with exact integer square-root bounds. There is no numerical tolerance or
unverified fixed-radius shortest-vector search.

### Faces and equivalence

Every relevant cell contains an independent minimal-vector frame, so it appears
on a face of one of the enumerated slices. A face of affine dimension `f` gives
a cone of dimension `n(n+1)/2 - f`. The search checks this identity against the
rank of its complete set of rank-one generators.

Canonicalization considers every signed ordered unimodular frame in ranks 1--3.
In rank 4 it first minimizes the intrinsic Gram tuple over those frames, then
minimizes the coordinate configuration among the tied frames. Both stages are
invariant under ambient integral equivalence, so equivalent configurations have
the same key; identical keys give an explicit integral unimodular equivalence.
Stabilizers are computed from actual linear maps preserving the vector pairs;
they are not inferred from arbitrary permutations of rays. Orientation is the
determinant of the action on the rank-one matrix span, even when rays are
linearly dependent, as for D4.

Background: [Schurmann, Enumerating perfect forms, Section 3](https://arxiv.org/pdf/0901.1587)
explains local finiteness of Ryshkov polyhedra.

## Output and limits

The JSON contains integral ray vectors (one representative of each sign pair),
a rational Gram matrix whose **complete** minimal-vector set consists of those
pairs, cone and projective dimensions, stabilizer order (including `-Id`), and
whether the stabilizer contains an orientation-reversing element. Rational
matrix entries are strings such as `"1/2"`, never approximate decimals.

The console's orientation-preserving count includes a cell only when **every**
stabilizer element preserves its orientation. These are the generators used by
the usual free Voronoi complex after inverting 2. Orientation-reversing cells
are still retained in the JSON.

The options `--max-grid-points`, `--max-vertex-systems`, `--max-edge-tests`, and
`--max-faces` bound brute-force work. Vertex systems and edge-pair tests are
bounded per frame; face count is bounded across the entire run.
Exceeding a limit raises `SearchLimit` (CLI exit status 2).
No successful partial result or new JSON file is written on such a failure.
If a previous output file already exists, it remains unchanged.

Use `--polyhedron-method clipping` to run the incremental backend in smaller
ranks; `--polyhedron-method active-sets` selects the original independent
backend. The test suite compares their exact vertex sets in ranks 1--3. The
active-set backend exceeds its default work limit in rank 4, as intended.
`--verbose` reports frames and newly discovered orbits to stderr.

The prototype does **not** assemble boundary matrices, compute homology, or
support n>=5. Removing the rank guard would invalidate the frame bound and
canonicalization argument as well as make this slice-vertex strategy expensive.

No computation of K12 is performed; this is a small-rank reference for the
enumeration component.
